# ChangeSpec — Design Document

## Overview

Phase 7c (ChangeSpec) generates **human-readable change specification documents** from source code changes. While Phase 7 (Drift Detection) answers "*which spec sections are affected by code changes?*", Phase 7c answers "*what changed, why, and what does it mean?*"

This feature aims to replace manual changelogs and review summaries. It describes change sets in natural language with enough detail that readers can understand the changes without reading the raw diff.

## Design Goals

1. **Zero external dependencies** — `scripts/change-spec.py` uses stdlib only
2. **Leverage existing artifacts** — reuse `source-map.json`, `trace.json`, and Phase 7's git diff parsing
3. **Extraction is mechanical** — the Python script extracts facts only, never interpretation
4. **Interpretation is AI-driven** — natural language explanations are generated by the AI agent (Phase 7c) reading `change-spec.json`
5. **Optional** — user confirms via AskUserQuestion before generation
6. **Dual mode** — supports both git diff (full detail) and hash comparison (limited detail)

## Dataflow

```
git diff -U5 <base>
  or
source-hashes.json + current files
        |
        v
scripts/change-spec.py  (mechanical, stdlib only)
  - Parse unified diff or hash changes
  - Detect structural changes (symbols, imports)
  - Cross-reference with source-map.json / trace.json
  - Output: {output_dir}/change-spec.json
        |
        v
AI Agent (Phase 7c SKILL.md procedure)
  - Read change-spec.json
  - Generate natural language explanations
  - Output: {output_dir}/change-spec.md
```

## change-spec.json Schema

```json
{
  "schema_version": "0.1.0",
  "mode": "git | hash",
  "base": "HEAD | hash-snapshot | <ref>",
  "generated_at": "2026-07-29T...",
  "summary": {
    "total_files": 5,
    "insertions": 245,
    "deletions": 89,
    "by_type": {
      "A": 1,
      "M": 3,
      "D": 1
    }
  },
  "files": [
    {
      "file": "app/models/issue.rb",
      "status": "M",
      "insertions": 8,
      "deletions": 3,
      "structural_changes": {
        "added_symbols": ["assigned_member"],
        "removed_symbols": [],
        "modified_symbols": ["assignee"],
        "added_imports": [],
        "removed_imports": []
      },
      "before_snippet": "...",
      "after_snippet": "...",
      "impacted_sections": [
        {"file": "02-entities.md", "section": "2.1 Issue"}
      ]
    }
  ]
}
```

### Hash mode additional fields

In hash mode, `structural_changes` includes extra keys:

```json
{
  "structural_changes": {
    "added_symbols": [],
    "removed_symbols": [],
    "modified_symbols": [],
    "current_symbols_HASH_ONLY": ["assignee", "assigned_member"],
    "current_imports_HASH_ONLY": ["json", "typing"]
  }
}
```

These `_HASH_ONLY` fields are derived from the current file content only (no before/after comparison possible) and indicate lower confidence.

## Mode Comparison

| Aspect | Git Mode | Hash Mode |
|--------|----------|-----------|
| Input | `git diff -U5` | `source-hashes.json` + current files |
| Before code | Available from diff | Not available (no history) |
| Line-level detail | Full (added/removed lines) | None |
| Symbol detection | Accurate (diff-based) | Current structure only |
| Import change detection | Net add/remove/modify | Current imports only |
| Snippet quality | Before + after code | After code only |
| Confidence | HIGH | LOW (inferred) |
| Use case | Git-managed projects | Non-Git projects / snapshots |

## Symbol Detection Coverage

Language-specific regex patterns for detecting function/class/method definitions from diff lines:

| Extension | Detects | Example |
|-----------|---------|---------|
| `.py` | `def`, `async def`, `class` | `def process():` |
| `.rb` | `def`, `class`, `module` | `def assignee` |
| `.js`/`.ts` | `function`, `class`, `const/let/var` | `function render()` |
| `.go` | `func` | `func main()` |
| `.java` | `class`, method declarations | `public class Handler` |
| `.cs` | `class`, `struct`, method declarations | `public class Service` |
| `.php` | `function`, `class` | `public function handle()` |

Language-specific import pattern detection:
- Python: `import X`, `from X import Y`
- Ruby: `require`, `require_relative`, `include`, `extend`
- JS/TS: `import ... from`, `require()`
- Go: `import "pkg"`
- Java: `import pkg.Class`
- C#: `using Namespace`
- PHP: `use Namespace\Class`

## Output Quality Standards

`change-spec.md` must follow these quality standards:

1. **Self-contained**: Readers should understand changes without opening source files
2. **Before/After**: Show both versions of changed code (git mode)
3. **Intent**: Explain why the change was made (from naming, comments, context)
4. **Impact**: Link to affected spec sections when applicable (from trace.json)
5. **Breaking changes**: Clearly flag API signature changes, deletions, default value changes
6. **Migration steps**: Describe migration paths when breaking changes exist
